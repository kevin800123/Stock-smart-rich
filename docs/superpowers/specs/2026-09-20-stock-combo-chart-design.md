# 個股頁三張圖合成一張（K 線 × 法人 × 集保）設計

日期：2026-09-20　狀態：使用者已核准設計

## 問題

個股頁現在是三張各自為政的圖，由上而下：
- `#stock-chart`：Lightweight Charts v5（價格窗格＋量能窗格），有 時／日／週／月 切換、均線、艾略特波浪標記、最後收盤價標籤。
- `#stock-chips`：ECharts 堆疊柱，個股三大法人買賣超，日頻、近 60 日（`/api/stock/{code}/chips?days=60`）。
- `#stock-custody`：ECharts 兩條折線（千張大戶%、400張↑%），週頻、可到約一年（`/api/stock/{code}/custody`）。

三張的 X 軸各自獨立，答不出這頁真正要答的問題：**價格轉折那天，法人在買還是在賣、大戶在收還是在散**。使用者提供 XQ 的
「價量累計圖」作為參考：一條時間軸、十字線貫穿所有副圖、每個副圖左上角一行讀數、副圖很矮。

## 使用者的決定（2026-09-20）

1. 目的是**對照轉折**：同一條時間軸、十字線貫穿，縮放平移三格一起動。
2. 三大法人那格**自己寫堆疊柱**，維持現在的外觀（外資／投信／自營疊成一根）。
3. 數字**放在每格左上角一行**（跟著十字線走），不用浮動 tooltip。
4. K 線切到週／月時，法人與集保**跟著聚合**；時 K 沒有對應資料，兩格收起。
5. 預設視窗是**最近 60 個交易日**（三格都有資料的區間），可自己往左拉。
6. 架構**留在 Lightweight Charts**（維持滾輪縮放、拖曳平移的手感），不改回 ECharts。
7. 桌機總高約 **560px**。
8. 集保的「補歷史」連結**拿掉**，改成第一次查該檔時**自動在背景補**。
9. 集保那格要有 XQ 那種**人均數箭頭**：比上週高＝白色向上、低＝黃色向下。

## 設計

### 1. 版面

一個 Lightweight Charts 實例、四個窗格共用時間軸與十字線：

| 窗格 | 桌機高 | 手機（≤600px）高 | 內容 |
|---|---|---|---|
| 價格 | 300 | 240 | K 棒、均線、艾略特波浪標記、最後收盤價標籤（皆維持現狀） |
| 量能 | 70 | 55 | 成交量柱（現狀） |
| 法人 | 95 | 80 | 外資／投信／自營堆疊柱（新，自訂繪圖） |
| 集保 | 95 | 85 | 千張大戶%、400張↑% 兩條階梯線＋人均數箭頭（新） |

容器總高 560px（手機 460px），沿用既有 `#stock-chart { contain: size }`（防止 flex 容器與 `autoSize` 互相把高度愈撐愈大，這是踩過的坑）。窗格分隔線用函式庫內建的拖曳調整，不記憶狀態。

### 2. 每格左上角的讀數列

絕對定位在各窗格左上角、`pointer-events: none`，十字線移到哪根就顯示那根的值，滑鼠離開時回到最新一根：

- 價格：`09/18 開 550.00 收 558.00 +13.00 (+2.39%)`（漲跌沿用紅漲綠跌）
- 量能：`4,760 張`
- 法人：`外資 +1,242　投信 −80　自營 +33　合計 +1,195`（張；紅買超綠賣超）
- 集保：`千張大戶 77.9%　400張↑ 83.0%　人均 94,463 股（09-18）`

取代現有的浮動 tooltip。移除 tooltip 時，`disposeStockChart` 既有的「清掉殘留覆蓋層」也要跟著改成清這四行讀數列——反覆查詢時 DOM 節點會疊加，這是踩過的坑。

### 3. 資料與聚合

三支既有 API 不變：K 線、`/api/stock/{code}/chips?days=60`、`/api/stock/{code}/custody`。**合併只在前端做**，不開後端合併端點——日期對齊是呈現層的黏合，不是分析邏輯（沿用「大盤×籌碼對照圖」的既有決定）。

- **日 K**：法人逐日對齊；集保逐週對齊。
- **週 K**：法人按該週加總；集保本來就是週資料，直接對上（一根 K 棒對一筆）。
- **月 K**：法人按該月加總；集保取該月最後一週。
- **時 K**：法人與集保兩格收起（沒有逐小時的籌碼資料），只留價格與量能。

**籌碼日期一律貼到 K 線已有的那根棒子上**：找「≤ 該日期的最後一根 K 棒」，貼過去；同一根棒子被貼到多筆時取最新一筆。理由：Lightweight Charts 的時間軸是所有 series 時間的聯集，直接丟進不存在的日期（集保週五遇假日、`stock_ohlc` 稀疏）會多出沒有 K 棒的刻度，看起來像破圖。貼不到任何一根（早於第一根 K 棒）就丟掉。

### 4. 三大法人堆疊柱（自訂繪圖）

Lightweight Charts 沒有內建堆疊柱，所以用它的自訂 series 介面畫一層：每根棒子上，正值由 0 往上依序疊（外資→投信→自營），負值由 0 往下依序疊，顏色沿用現有的 `SER.foreign`／`SER.trust`／`SER.dealer`（藍／紫／橘），與現在那張圖一致。柱寬跟著時間軸的棒距走。三個值皆為空的那根不畫。

### 5. 集保與人均數

- 兩條**階梯線**（`lineType: with-steps`）：一週一階，符合「這一週就是這個值」的語意。顏色沿用現在的兩色。
- **人均數＝集保總股數 ÷ 總持股人數**（單位：股）。目前 `custody_dist` 只存人數與比例，**沒有股數**，所以：
  - `custody_dist` 新增 `total_shares REAL`（lazy migration，同 `total_holders` 的既有做法）。
  - `sources/tdcc.py::_aggregate_levels` 多算一項「分級 1~15 的股數加總」；兩個來源都要傳進股數——
    opendata CSV 的第 5 欄、智能網 HTML 的第 4 格（兩邊本來就有這一欄，只是沒用）。
  - 人均數在**後端**算（`/api/stock/{code}/custody` 的 trend 每週多回一個值），任一輸入缺就回空值，
    不在前端算第二份（同全站「算式只有一份權威版本」的規矩）。
- **箭頭**：每週一個，掛在千張大戶那條線上——比上週高＝白色向上箭頭、低＝黃色向下箭頭；相等或任一週缺值就不標；
  第一週沒有前一週可比，不標。
  **密度是已知風險**：一年約 52 個箭頭在 95px 高的格子裡可能過密。先照使用者要的「每週都標」實作並實測截圖；
  太密時的備案是只標「方向轉變」的那幾週，由使用者看過再決定（不在這份規格裡預先改掉）。

### 6. 自動補歷史（拿掉連結）

- 進入個股頁載入集保資料時，若該檔**完整週數 < 30 週**，或**有股數的週數 < 已存週數的一半**（舊資料沒有股數欄），
  就在背景補約 52 週（沿用既有 `/api/stock/{code}/custody/backfill` 的抓取邏輯與 `_custody_lock`）。
- **節流**：每檔每天最多自動補一次（`ai_cache` 記 `custodyauto:{code}:{date}`）；同一時間只允許一個補歷史在跑
  （已有的鎖），拿不到鎖就這次不補、下次再說。手動查很多檔時不會連續打 TDCC 智能網。
- **不阻塞畫面**：集保 API 立刻回現有資料並附 `backfilling: true`；前端照常畫圖，之後每 5 秒重問一次，
  補完（`backfilling: false` 且週數變多）就重畫那一格，最多問 24 次（2 分鐘）後放棄。
  背景執行緒自己開一條 sqlite 連線（sqlite 預設不跨執行緒共用），沿用 `PRAGMA busy_timeout`。
- 智能網逐週抓、每次要帶上一次回應輪替的 CSRF token，52 週約半分到一分鐘——這就是為什麼只能背景做。
- 畫面上的「補歷史」連結移除；`/api/stock/{code}/custody/backfill` 端點**保留**（手動重補、除錯時仍用得到）。

### 7. 移除與保留

- 移除：`#stock-chips-wrap`／`#stock-chips`／`#stock-custody-wrap`／`#stock-custody` 容器、`loadStockChips`／
  `loadStockCustody` 兩支 ECharts 載入器、`stockChipsChart`／`stockCustodyChart` 兩個實例與 window resize 掛勾裡的它們、
  只服務 chips 的 `trimEdges`（若無其他呼叫端）、集保「補歷史」連結與它的 click handler。
- 保留：三支 API、艾略特波浪與轉折%滑桿、時／日／週／月 切換、K 線資料缺口提示（`KLINE_GAP_DAYS`）、
  個股頁其餘區塊（基本面、估價、股期保證金等）。

### 8. 空狀態與失敗

- 某一格完全沒有資料（例如這檔沒有三大法人資料、或集保查無）：**那一格留著但清空、讀數列顯示「—」**，並在 K 線上方的
  說明列註明原因（沿用現有 `stock-note` 的寫法）。窗格是跟著 series 走的，動態移除 series 會讓下一檔有資料時無從恢復——
  寫計畫時對回程式碼才發現，原本寫的「那一格不建立」做不到。
- K 線本身查無資料：維持現狀（丟掉圖表實例、顯示「尚無資料」）。
- 任一支 API 失敗：只影響它那一格，其餘照畫；說明列註明「（載入失敗）」。

## 風險與驗證

沒有前端自動化測試，所以驗證一律是**在瀏覽器對真實資料實測**，並且要能反證：

1. **堆疊柱的正確性**：拿真實的一檔股票，逐根把畫面上的堆疊柱與 `/api/stock/{code}/chips` 的原始數字比對
   （正負混合那幾根一定要涵蓋）；反證：把外資那段的資料改成 0，柱子要跟著少一段。
2. **對齊**：刻意塞一筆「不在 K 線日期裡」的集保週（例如週五遇假日），確認軸上不會多出沒有 K 棒的刻度
   （本機資料剛好對齊時，綠燈證明不了任何事——這是踩過的坑）。
3. **週／月聚合**：法人按週加總的結果，與自己把日資料相加的答案逐根比對。
4. **讀數列**：用時間軸與價格軸的座標換算，觸發十字線停在某一根，把四行讀數與原始資料逐欄比對。
5. **版面**：1560／1280／375px 三個寬度量四個窗格的實際高度、頁面不得有水平溢出；切走再切回個股頁時四個窗格的
   尺寸要正確（`autoSize` 在「隱藏→顯示」的跳變上不可靠，既有程式已有手動 resize 的處理，要跟著擴充）。
6. **自動補歷史**：用一檔沒有歷史的股票實跑一次，確認圖先畫出來、背景補完後集保那格自己變長；
   同一天再查同一檔不會再補（節流）；反證：把節流拿掉會看到第二次又在抓。
7. **人均數**：拿真實一週的分級資料，手算「分級 1~15 股數加總 ÷ 人數加總」與後端回傳值比對；
   箭頭方向與相鄰兩週的人均數大小關係逐點比對。

後端新增的部分（`total_shares` 欄位、人均數、自動補歷史的節流與判斷）照專案慣例寫 pytest：
純解析函式用小樣本鎖契約，端點用 `TestClient` ＋ monkeypatch 假 fetch，每道守衛都要有反證。

## 不做的事

- 不加「資券」「威廉」「金叉」等 XQ 有、我們沒有的副圖（YAGNI；資券的逐檔資料雖然存在，但這次沒有要求）。
- 不做窗格勾選／自訂排列（先固定四格；真的需要再說）。
- 不改後端 API 形狀以外的東西：不新增「合併好的」端點、不動 K 線資料流程。
- 不把 `/chips` 的 60 日上限拉長（逐日快取，拉長會讓沒預熱的日期逐一連外，很慢）；
  預設視窗本來就是 60 日，更早的區間法人那格留白。
